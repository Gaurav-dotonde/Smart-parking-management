1. Confirmed root cause
- The admin UI was reading shared list data through inconsistent assumptions, but the biggest live blocker was backend entity serialization on `GET /api/lots`.
- Before the fix, `/api/lots` returned a recursive `parking_lots -> slots -> parkingLot -> slots ...` JSON graph, which made the payload huge and unsafe for the frontend to consume.
- File path: backend/src/main/java/com/parking/model/ParkingLot.java:53-56
- Current code: `@JsonIgnore` was added to the `slots` back-reference so the lot list no longer serializes the full recursive graph.
- Why it prevented display: the frontend could not reliably parse and use the lot list because the response was effectively an endlessly nested entity graph instead of a clean finite list.

3. Exact changes made
- Added a shared response normalizer `unwrapList()` in `frontend/src/services/parkingService.js`.
- Updated admin and user list pages to use the normalizer and to refresh after create/update/delete events.
- Added a local in-flight submit guard in `AdminLots.jsx` so one click sends one POST.
- Added success feedback in `AdminLots.jsx` after create/update.
- Changed the Axios interceptor in `frontend/src/services/api.js` to preserve 401/403 errors and log failed requests in development instead of auto-redirecting and hiding the real error.
- Added backend duplicate-lot validation in `ParkingLotService.createLot()` and `updateLot()` using trimmed name + location.
- Added `@JsonIgnore` to `ParkingLot.slots` so `GET /api/lots` returns a finite list.
- Updated `AdminPanel.jsx` to use `Promise.allSettled()` so one lot’s slot fetch does not blank the entire Manage Slots page.
- Added dashboard refresh on data-change events and window focus.

6. Duplicate request fix
- `AdminLots.jsx` now uses the form `onSubmit` only, with no separate duplicate submit click handler.
- `savingRef.current` blocks repeat submissions while a POST/PUT is in flight.
- The submit button is disabled while saving.
- The lot service now trims `name` and `location` before duplicate checking.
- The backend now rejects identical name + location lots with HTTP `409 Conflict`.
- Expected message: `A parking lot with this name and location already exists.`

7. Jackson serialization fix
- `ParkingLot.slots` is marked with `@JsonIgnore` so `GET /api/lots` no longer emits recursive slot nesting.
- Live verification after backend restart showed the recursion was gone and the lot list became a finite array.
- `GET /api/lots/1/slots/admin` remains a DTO list, so Manage Slots consumes a stable non-recursive payload.
